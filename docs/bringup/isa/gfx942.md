Notes:
* Workgroup→XCD placement is round-robin, block `b` on XCD `b % 8`, measured 100.0% on MI300X and MI355X [measured in plow: `runtime/amd/interp.hip` kernel-entry `HW_REG_XCC_ID` comment]. Read `HW_REG_XCC_ID` (`s_getreg_b32`) instead of deriving the XCD.
* The default persistent grid is one workgroup per CU, so `IsaLevel::Gfx942.geometry().lds_bytes = 65536` is the whole per-CU budget. An oversubscribed grid (`PLOW_OVERSUB`) spins forever unless the object's VGPR/LDS fit every co-resident workgroup (`crates/plowrt/src/exec/amd.rs`).
* `PLOW_LDS_MAX_BYTES 65536` (`runtime/amd/amd_arch.h`); the cap is enforced by the compiler ("local memory (N) exceeds limit (65536)"), not at launch.

## 2. Matrix instructions (MFMA)

Cycle counts from CDNA3 ISA Table 28; 1 pass = 4 cycles (ISA 7.5). Rate per SIMD = M*N*K / cycles.

| mnemonic (LLVM asm) | A/B | acc | cycles (passes) | MAC/clk/SIMD | regs A,B / C,D | plow use |
|---|---|---|---|---|---|---|
| `v_mfma_f32_32x32x8_bf16` (old spelling `..x8bf16_1k`) | bf16 | f32 | 32 (8) | 256 | 2,2 / 16 | `amd_arch.h:plow_mfma_bf16_32x32` (issued twice per 32x32x16 fragment) |
| `v_mfma_f32_16x16x16_bf16` | bf16 | f32 | 16 (4) | 256 | 2,2 / 4 | `amd_arch.h:plow_mfma_bf16_16x16` (issued twice) |
| `v_mfma_f32_32x32x8_f16`, `16x16x16_f16` | f16 | f32 | 32 / 16 | 256 | same | not used |
| `v_mfma_f32_32x32x16_fp8_fp8` (+`_bf8_bf8`, `_fp8_bf8`, `_bf8_fp8`) | e4m3**fnuz** / e5m2**fnuz** | f32 | 32 (8) | 512 | 2,2 / 16 | `amd_arch.h:plow_mfma_fp8_32x32` (4 issues = K64); `scripts/asm_expect_gfx942.json` requires it per kernel in the fp8 GLU objects, forbids it in the bf16 GLU and `interp_prefill*` kernels |
| `v_mfma_f32_16x16x32_fp8_fp8` (+ variants) | fp8/bf8 fnuz | f32 | 16 (4) | 512 | 2,2 / 4 | not used |
| `v_mfma_i32_32x32x16_i8`, `v_mfma_i32_16x16x32_i8` | i8 | i32 | 32 / 16 | 512 | 2,2 / 16,4 | not used |
| `v_mfma_f32_32x32x4_xf32`, `16x16x8_xf32` | f32 rounded to 10-bit mantissa | f32 | 32 / 16 | 128 | 2,2 / 16,4 | not used; gfx942-only (absent on gfx950: LLVM `FeatureXF32Insts` only in 9_4_2) |
| `v_mfma_f64_16x16x4_f64` | f64 | f64 | 32 (8) | 32 | | not used |

Peak check: 32x32x8 bf16 = 8192 MAC / 32 clk = 256 MAC/clk/SIMD x 4 x 304 x 2.1 GHz x 2 = 1307 TF, matching the data sheet [vendor documented]. White paper flops/clk/CU: 2048 bf16/f16, 4096 fp8/int8.

**Operand layout** (ISA 7.1.4; `K_L = K / (64 / M)` items per lane, little-endian packed):

| instr | A lane `l` holds | B lane `l` holds | D/C item `r` of lane `l` |
|---|---|---|---|
| 32x32x8 bf16 | row `l%32`, k = `4*(l/32) + 0..3` | col `l%32`, same k | row `8*(r/4) + 4*(l/32) + r%4`, col `l%32` (16 items) |
| 16x16x16 bf16 | row `l%16`, k = `4*(l/16) + 0..3` | col `l%16`, same k | row `4*(l/16) + r`, col `l%16` (4 items) |
| 32x32x16 fp8 | row `l%32`, k = `8*(l/32) + 0..7` (one 64-bit operand) | col `l%32` | as 32x32x8 |
| 16x16x32 fp8 | row `l%16`, k = `8*(l/16) + 0..7` | col `l%16` | as 16x16x16 |

* plow's fragment map is `MFMA_M/N/K = 32/32/16` on both CDNA arches (`amd_common.h`). CDNA3 splits each lane's 8 bf16 into two 4-element issues on the same accumulator; fp8 splits 32 bytes into four 8-byte issues. Both are k-permutations applied identically to A and B, so products are exact; only f32 accumulation grouping differs from gfx950 [measured in plow: `runtime/amd/amd_arch.h` header comment].
* Builtins: `__builtin_amdgcn_mfma_f32_32x32x8bf16_1k(a4, b4, acc16, cbsz, abid, blgp)`, `__builtin_amdgcn_mfma_f32_16x16x16bf16_1k`, `__builtin_amdgcn_mfma_f32_32x32x16_fp8_fp8(long a, long b, acc16, 0,0,0)`. `cbsz/abid/blgp` broadcast controls (ISA 7.1.5) are 0 everywhere in plow.
* Registers: A/B/C/D must be **even-aligned** VGPR tuples; A/B only VGPR/AGPR, C may be inline constant; MFMA ignores EXEC (forced all-ones), forces RNE, keeps denorms [vendor documented: CDNA3 ISA Table 28 footer]. Each MFMA's ACC bits choose arch VGPR or AGPR for A/B and for C/D; `v_accvgpr_read/write/mov_b32` move between files.
* AGPR vs VGPR accumulators: the compiler decides. Inlined megakernels grab AGPRs as spill relief and the arch+acc maxima **sum** (see Pitfalls); a 4-wave HIP GEMM put 40 16x16 accumulators in AGPRs at 210 VGPR + 160 AGPR, occupancy 1, on gfx950 [measured in plow: `runtime/ubench/GEMM_MFMA_SHAPE_VERDICT.md`]; read the gfx942 object before budgeting.

**Hazards / required waits** (ISA 7.5, Table 37; the compiler inserts these for builtins; **inline asm must insert them itself** with `s_nop N` = N+1 waits (N 0..15) or independent instructions):

| first | second | waits (2 / 4 / 8 / 16-pass first MFMA) |
|---|---|---|
| non-DL VALU writes VGPR | MFMA reads it | 2 |
| XDL MFMA writes D | same-shape MFMA reads it as C (exact overlap, back-to-back accumulate) | 2 / 0 / 0 / 0 |
| XDL writes D | XDL reads overlapping C (not exact) | 3 / 5 / 9 / 17 |
| XDL writes D | MFMA reads it as A or B | 5 / 7 / 11 / 19 |
| XDL writes D | VALU read/write, or VMEM/LDS/FLAT reads it as data | 5 / 7 / 11 / 19 |
| XDL reads C | VALU overwrites that C (WAR) | 1 / 3 / 7 / 15 |
| `v_cmpx` writes EXEC | any MFMA | 4 |
| SALU writes M0 | LDS-DMA (`global_load_lds_*`, `buffer_* lds`) | 1 |

Throughput: same-dst accumulate chains forward for free, so chain count is not a lever [measured in plow: `runtime/ubench/GEMM_MFMA_SHAPE_VERDICT.md` CDNA3 section: 1 chain = 914 TF/s vs 937 at 4 chains].

## 3. Conversions and dtypes

| op | gfx942 behaviour |
|---|---|
| `v_cvt_pk_f32_fp8` / `__builtin_amdgcn_cvt_pk_f32_fp8(w, hi)` | decodes **e4m3fnuz** (bias 8, `0x80` = NaN, max 240, no -0) [vendor documented: CDNA3 ISA 7.2 Table 30]. OCP byte value = 2 x FNUZ value for every byte except `0x80` (OCP -0, FNUZ NaN) and `0x7f`/`0xff` (OCP NaN, FNUZ ±240 → ±480 after doubling) [measured in plow: `amd_arch.h` "fp8 IS A DIFFERENT FORMAT" and the `plow_fp8x4_ocp_to_bf16` DIVERGENCE note] |

## 4. Memory movement

| path | widths | notes |
|---|---|---|
| `global_load_dword{,x2,x3,x4}` / `global_store_*` | 4-16 B / lane | 16 B/lane is the norm; `__builtin_nontemporal_load/store` → `nt` |
| `buffer_load_dword{,x2,x3,x4}` via `__builtin_amdgcn_make_buffer_rsrc` + `__builtin_amdgcn_raw_buffer_load_b{16,32,64,128}(rsrc, voff, soff, aux)` | 2-16 B | raw bounds check: `inst_offset + voff >= num_records` (bytes) returns 0 / drops the store, per dword for x2-x4; `soff` is **not** checked, bound it yourself [vendor documented: ISA 9.1.5.1]. `aux`: bit0 = `sc0`, bit1 = `nt`, bit4 = `sc1` (`aux=3` → `sc0 nt`) [measured in plow: `interp.hip` sc1 note; vendor documented: ISA 9.1.10.2] |
| `global_load_lds_{ubyte,sbyte,ushort,sshort,dword}`, `buffer_load_* ... lds` | **1/2/4 B per lane only** (no dwordx3/x4 on gfx942) | LDS-DMA: no VGPRs, tracked on `vmcnt`; LDS destination = `M0` (wave-uniform) + `lane * 4` for every gfx942 form: byte/short loads are zero/sign-extended to 32 bits, so the lane stride is 4 B, not the transfer size [vendor documented: ISA 10.3 (`DWORDX1 ... ThreadID*4`), 12.15.3 `GLOBAL_LOAD_LDS_*`, Table 54, 11.2; measured in plow: `amd_common.h` `[LDS-DMA-4B]`] |
| `ds_read_b{32,64,96,128}`, `ds_read2_b32/b64`, `ds_write_*` | 4-16 B | `ds_read_b128` needs a 16 B-aligned address or it degrades (see Pitfalls). **No `ds_read_b64_tr_b16`** (gfx950 only; absent from CDNA3 ISA) |
| `ds_bpermute_b32`, `ds_swizzle_b32`, DPP | cross-lane | `ds_swizzle` does not touch LDS banks; `ds_bpermute` goes through the LDS crossbar |

**Cache policy bits** (gfx942 renamed glc/slc/scc → `sc0`/`nt`/`sc1`; ISA 9.1.10.2 Tables 48-49; scope = `SC[1:0]`):

| `sc1 sc0` | scope | loads | stores |
|---|---|---|---|
| 0 0 | wave | L1 hit/LRU | L1 miss, L2 LRU |
| 0 1 | group | L1 hit (miss if tgsplit) | as wave |
| 1 0 | device | **L1 bypass**; L2 hit only if 1 L2, else coherent bypass (multi-XCD gfx942 = bypass non-local lines) | write-through |
| 1 1 | system | L1 + L2 coherent bypass | write-through |
| `nt=1` | any | L1 miss-evict; L2 hit-stream at wave/group scope (device/system scope on multi-XCD: coherent bypass); LLC evict | same |

Atomics: `sc0` = return pre-op value, `sc1` = system (vs device) scope, `nt` = LLC no-allocate. RMW atomics always bypass L1.

**LDS banking**: 32 banks x 4 B; dword `d` lives in bank `d % 32`; a wave's request is dispatched over 4 cycles; conflicts serialize (2 to 64 cycles) [vendor documented: ISA 11.1, 11.3.1]. Phase grouping of `ds_read_b64/b128` lanes per cycle: (UNVERIFIED). plow's GEMM row pad `+8 halves` (16 B) per row breaks the 32-rows-at-one-k conflict (`GemmTile::PAD_HALVES`, `crates/hwspec/src/isa.rs`).

## 5. Synchronization and ordering

* `s_waitcnt`: `vmcnt` 6 bits (SIMM16[3:0] + [15:14]), `expcnt` 3 bits [6:4], `lgkmcnt` 4 bits [11:8] [vendor documented: ISA 3.1, S_WAITCNT]. Builtin `__builtin_amdgcn_s_waitcnt(0x0f70)` = `vmcnt(0)` (`interp.hip:ctr_signal`). LDS-DMA loads count on `vmcnt`, not `lgkmcnt`. Counters cover only the issuing wave: before an `s_barrier` that publishes LDS, wait `lgkmcnt(0)` (`vmcnt(0)` for LDS-DMA).
* `__syncthreads()` = fence + `s_barrier` + fence; the compiler inserts the waits. A raw `s_barrier` (asm or `__builtin_amdgcn_s_barrier`) inserts none: wait explicitly before it. `s_setprio N` (0-3) biases issue between co-resident waves on a SIMD (`op_gemm_common.h` ping-pong).
* Cache maintenance (ISA Tables 50-51, AMDGPUUsage GFX942):

| instruction | effect on gfx942 |
|---|---|
| `buffer_inv sc1` | invalidate L1 + non-local L2 lines — what an **agent**-scope acquire emits |
| `buffer_inv sc0 sc1` | system-scope acquire (other agents / host) |
| `buffer_inv sc0` | L1 only, and only meaningful in tgsplit mode; else NOP |
| `buffer_inv` (no bits) | cache-maintenance NOP that still increments `vmcnt`, even with EXEC=0 (LLVM AMDGPUUsage gfx942 memory model); the compiler never emits it |
| `buffer_wbl2 sc1` | write back dirty L2 — agent-scope release |
| `buffer_wbl2 sc0 sc1` | system-scope release |

* Scopes: `__hip_atomic_*(…, __HIP_MEMORY_SCOPE_{WAVEFRONT,WORKGROUP,AGENT,SYSTEM})`, `__builtin_amdgcn_fence(order, "workgroup"|"agent"|"")` (`""` = system). Workgroup-scope acquire emits no cache maintenance (`buffer_inv sc0` only under `-mtgsplit`, which plow does not use). Because L2 is per-XCD, any cross-workgroup handoff inside one GPU needs **agent** scope; cross-GPU (xGMI peer VRAM) needs **system** scope.
* plow's gate idiom (`interp.hip` `ctr_poll/ctr_acquire/ctr_signal`, cross-GPU twins `op_collective.h` `xctr_*`): relaxed polling load, one acquire fence after the gate clears, release on the signalling RMW. An acquire *load* emits `buffer_inv` on every poll iteration; a standalone release fence is heavier than the RMW's own release (coarse decode 16.8 → 17.4 ms/token) [measured in plow: `interp.hip` `ctr_signal` comment].
* Scheduling hints: `__builtin_amdgcn_sched_barrier(mask)`, `__builtin_amdgcn_sched_group_barrier(mask, size, syncid)`; masks 0x2 VALU, 0x8 MFMA, 0x20 VMEM read, 0x100 DS read, 0x200 DS write, 0x800 LDS-DMA [vendor documented: AMDGPUUsage intrinsics table]. Used in `op_moe.h` (`PLOW_MOE_PF_SCHED`, default off). They change order only.
* Peer memory: `plow_hsa_alloc_peer` = coarse-grained VRAM made visible with `hsa_amd_agents_allow_access` naming every GPU agent (`runtime/amd/hsa_backend.c`); the call replaces the access list, and the pool owner keeps access (`hsa_ext_amd.h`). Kernel-to-kernel cross-GPU sync is a system-scope atomic on that memory, ~90 ns one-way [measured in plow: `runtime/amd/op_collective.h` header].

## 6. Toolchain as plow uses it

* Compiler: `hipcc` from ROCm 7.14.1 (clang-23) in `nix develop`; `scripts/build_gfx942.sh` refuses a `hipcc` / `clang-offload-bundler` outside the nix store (`require_nix_tool`). clang-23 made the global operand of `__builtin_amdgcn_global_load_lds` non-const: `cp_async4` and the CDNA4 arm of `cp_async16` are version-gated; the CDNA3 arm of `cp_async16` is a VGPR copy (`amd_common.h`).
* Per-row compile (`scripts/build_gfx942.sh` `one()`; `runtime/cmake/hipcc_hsaco.sh` is the CMake twin):
  `hipcc --offload-arch=gfx942 -O3 -w -DPLOW_ARCH_SUFFIX=gfx942 <axes> --genco runtime/amd/interp.hip -o X.co`
  then `clang-offload-bundler --unbundle --type=o --targets=hipv4-amdgcn-amd-amdhsa--gfx942`.

* Decode profiles: default occupancy 2 (`__launch_bounds__(512,2)` + `amdgpu_waves_per_eu(2,2)`); `PLOW_OCC4=1` = GM 128x256x32, `PLOW_NO_MLA_DEC=1`, `PLOW_WPE=5` → 104 VGPR, 30,736 B LDS, 4 waves/SIMD; refused with `PLOW_DECODE_BATCH>1` (`PLOW_DEC_SQUEEZE=1` = validated WPE=3 recut).
* Builtin / inline-asm style used here:

```cpp

acc = __builtin_amdgcn_mfma_f32_32x32x8bf16_1k(a0, b0, acc, 0, 0, 0);

```

## 7. Pitfalls

1. **FP8 is e4m3fnuz on this silicon, OCP in plow's packets.** Hardware cvt halves every value and turns OCP `-0` (`0x80`) into NaN; a NaN-poisoned GEMV reported "PASS rel 0.0000" because `rel > worst` is false for NaN. Decode with `plow_fp8x4_ocp_to_bf16` (mask `0x80`, cvt, x2) or software; feed MFMA OCP bytes and fold `PLOW_FP8_MMA_FIX = 4.0` into the epilogue. Device-encoded CDNA3 streams never emit `0x80` by construction. [measured in plow: `runtime/amd/amd_arch.h`; vendor documented: CDNA3 ISA 7.2 Table 30]. Torch on gfx942 refuses `e4m3fn` in `_scaled_mm`; ceilings must use `e4m3fnuz` [measured in plow: `perf-data/tools/bringup_ceiling.py:fp8_dtype`].
2. **Arch + acc register maxima sum.** Inlined ops at 256 arch + 128 AGPR = 384 → 1 wave/SIMD, and an 8-wave dispatch is rejected with `HSA_STATUS_ERROR_INVALID_ISA`. `amdgpu_waves_per_eu(2,2)` makes the allocator spill instead [measured in plow: `runtime/amd/interp.hip` comment above `PLOW_ARCH_SUFFIX`].
3. **Set `__launch_bounds__(T, PLOW_WPE)` and `amdgpu_waves_per_eu(PLOW_WPE, PLOW_WPE)` together.** `__launch_bounds__(T, N)` expands to `amdgpu_waves_per_eu(N)`, a register ceiling the allocator fills: a stale N=2 let decode spend 253 VGPR; `PLOW_WPE=5` gives 104 [measured in plow: `interp.hip` launch-bounds comment; `scripts/build_gfx942.sh` OCC4 block]. The OCC4 ration (WPE 4/5) hangs batched decode's first dispatch [measured in plow: `scripts/build_gfx942.sh` 2026-08-10 bisect].
4. **Count spills from the ISA.** Objects have reported `.vgpr_spill_count: 0` and issued 119 `scratch_load_dword`; `buffer_*` weight streams are not spills [measured in plow: `scripts/plow_isa.py` header]. A rewrite that needed 48 B `private_segment_fixed_size` failed the loader's resource ABI check at serve start [measured in plow: 9af018a5].
5. **64 KiB LDS forces the tile.** 256x256x64 double-buffered = 147,456 B (2.25x over); gfx942 ships single-buffered 192x256x64 = 64,512 B. At BK=64 double-buffering (4*(BM+BN)*72 B) caps BM+BN at 224; with the fused-GLU wave grid (`SN == 2`, `op_gemm_common.h`) the shipped shape is 64x128, 2.8x worse [measured in plow: `crates/hwspec/src/isa.rs` `ArchGeometry`]; 128x256x32 double-buffered fits (61,440 B) but is 11.7% slower on prefill [measured in plow: `op_gemm_common.h` ping-pong-on-CDNA3 note]. A host mirror holding the gfx950 arena (73,728 halves) fused batches past gfx942 occ4's 15,360 and wrote past `plow_smem` — no batched-decode blob was correct on gfx942 [measured in plow: `docs/arch/14-amd-arch-divergence.md` §5]. Kernels needing >64 KiB (e.g. `k_intra_cached` 114,688 B) do not build here [measured in plow: `docs/amd/norm-and-recurrent-numerics.md`].
6. **LDS DMA is 4 B/lane max.** `__builtin_amdgcn_global_load_lds(..., 16, ...)` fails with "invalid size value", including in the host pass (guard with `__HIP_DEVICE_COMPILE__`). Four 4 B issues do **not** emulate one 16 B issue: the lane stride follows the issue width. `cp_async16`'s CDNA3 arm is a VGPR-staged copy [measured in plow: `runtime/amd/amd_common.h`]. Using real 4 B LDS DMA for flash K/V staging: prefill +21.7% at 70k [measured in plow: 54302e4e].
7. **Align the LDS arena to 16 B.** A 4 B-aligned arena turned `ds_read_b128` into `ds_read2_b32` pairs on gfx950 [measured in plow: `op_gemm_common.h` wave-count comment]; check LDS instruction selection in the gfx942 object.
8. **Use `PLOW_BUF_RSRC3` for descriptor word 3.** Zero (INVALID data format = unbound resource, ISA 9.1.4) compiles, runs, faults nothing and returns 0 for every lane [measured in plow: `runtime/amd/amd_common.h`].
9. **Divergent descriptor → waterfall.** A VGPR-resident base makes every `buffer_load_dwordx4` a readfirstlane/`s_cbranch_execnz` loop, one load per basic block, no clause. Use `buf_rsrc_u` / `buf_rsrc_fp8_u` (readfirstlane the base, optionally `PLOW_RSRC_SCALAR_N`) [measured in plow: `runtime/amd/amd_common.h`].
10. **L2 is per XCD.** Cross-workgroup handoff needs agent scope. `s_waitcnt vmcnt(0)` retires a store once it is written to the (per-XCD) L2 [vendor documented: CDNA3 ISA §4.4]; cross-XCD visibility additionally needs writeback/release at agent scope, so `PLOW_GATE_SC1` (sc1 stores + relaxed bump) is unsound [measured in plow: `interp.hip` `ctr_signal`]. Cross-XCD f32-atomic coherence: probe exists (`perf-data/tools/amd_atomic_coherence_probe.sh`), no gfx942 result recorded (UNVERIFIED).
11. **Cross-GPU: every edge at system scope.** An agent-scope arrival RMW on a line peers update at memory can lose counts on stale-line writeback; release fence + relaxed agent arrival failed the needle test [measured in plow: `runtime/amd/op_collective.h` `PLOW_XR_AGG`]. Never put a system acquire *load* in a spin. `hsa_amd_agents_allow_access` replaces the list: name every peer in one call [`hsa_ext_amd.h`; `runtime/amd/hsa_backend.c`]. Driver/IOMMU-level P2P visibility issues: none recorded in this tree (UNVERIFIED).
12. **Never write a bare `buffer_inv`: it invalidates nothing (but still bumps `vmcnt`).** Agent acquire = `buffer_inv sc1`, system = `buffer_inv sc0 sc1`, each after `s_waitcnt vmcnt(0)` on the acquiring load; or use `__builtin_amdgcn_fence` [vendor documented: CDNA3 ISA Table 51].
13. **Inline-asm MFMA or LDS-DMA bypasses hazard and alias tracking.** Insert Table 37 waits yourself; asm-defined VGPRs force `vmcnt(0)` inside the block; LDS-DMA alias tracking otherwise serialises fragment reads (why `mfp_dma` is asm) [measured in plow: `runtime/amd/moe_fp8_pf.hip`, `interp.hip` sc1 note].
14. **Shape is not the GEMM lever.** 16x16 issues 8.4% faster than 32x32 (1015 vs 937 TF/s); chain count is flat; hipBLASLt is at 91% of the issuable ceiling while plow prefill GEMM is ~52%; the remaining gap is staging schedule (`GM_CLBAR`, `GM_PLR`, `GM_PGR2`, ping-pong + `s_setprio`) [measured in plow: `runtime/ubench/GEMM_MFMA_SHAPE_VERDICT.md`]. Do not use producer/consumer wave specialisation: registers are partitioned statically per wave [measured in plow: `op_gemm_common.h`].
15. **No bf16 dot2.** Decode GEMV pays ~24 VALU per 16 B; usually hidden by memory latency at 2 waves/SIMD. A raw-f32 fp8 GEMV that won 8-11% standalone (256-reg budget) regressed 1% in the 104-reg megakernel [measured in plow: `runtime/amd/amd_arch.h` `plow_fp8x16_to_f32`].
16. **`-O3` without fast-math contracts `a - b*c` into one FMA** (changes norm variance bits; here it made it exact). Re-check emitted code before reasoning about rounding [measured in plow: `docs/amd/norm-and-recurrent-numerics.md` 1.3].
17. **Stale tuning records** — tunedb digest keys on implementation + interpreter + toolchain; any `-D` or ROCm bump silently reverts selection to the analytical model [measured in plow: `docs/amd/tp-bringup-mi300x.md` (4043 STALE records)].
18. **XCD-aware block order matters for weight re-streaming**: grouping an expert's tiles on one XCD lets its L2 serve weights once (+8% on the 64-row object's remap) [measured in plow: 6a6c92af].

## 9. Decision checklist

* Writing a matrix body → call `plow_mfma_bf16_32x32` / `plow_mfma_bf16_16x16` / `plow_mfma_fp8_32x32` from `amd_arch.h`; never a builtin only one CDNA level has. A new primitive goes in `amd_arch.h` with both arms.
* Touching fp8 bytes → assume OCP in memory, fnuz in hardware: mask `0x80`, use the x2 identity or `PLOW_FP8_MMA_FIX`; never `cvt_pk_f32_fp8` raw on packet bytes. Test with all 256 byte values and a NaN-aware comparator.
* Choosing tile/stages → compute `(BM+BN)*(BK+8)*2*buffers` against 65,536 B and the object's other LDS users; if it does not fit single-buffered, shrink BM/BN, do not drop the pad. Update `IsaLevel::geometry` only via the agreement test path.
* Choosing waves/occupancy → budget VGPR+AGPR together against 512/waves; set `__launch_bounds__` and `amdgpu_waves_per_eu` to the same WPE, then confirm VGPR/AGPR/spill from `plow_isa.py`, not from source.
* Staging global→LDS → 4 B/lane LDS DMA (`cp_async4`, `global_load_lds_dword`) when VGPRs are the constraint and the LDS layout is lane-contiguous at 4 B; otherwise 16 B `buffer_load_dwordx4` into registers with a two-deep prefetch (`GM_PGR2`).
* Streaming weights → `buffer_load_dwordx4` with uniform (`readfirstlane`) descriptor, word 3 `PLOW_BUF_RSRC3`, `aux=3` (`sc0 nt`); `num_records` handles tails in `voff`, not `soff`.
* Reading LDS fragments → 16 B-aligned `ds_read_b128`; pad rows by 16 B; check bank math against 32 x 4 B banks.
* Publishing data to another workgroup → agent-scope release RMW + relaxed poll + one agent acquire fence. To another GPU → system scope on every edge, peer buffer from `plow_hsa_alloc_peer`.
* Writing inline asm → add Table 37 waits (`s_nop`), explicit `s_waitcnt`, `"memory"` clobber, and an `asm_audit.py` expectation for the mnemonic.
* Prefill dense GEMM where native is far off → a segmented hipBLASLt/AITER object is allowed for prefill (separate AQL dispatch), not inside decode's one-dispatch-per-token interpreter (`docs/amd/aiter-tensile-notes.md`).
* MXFP4 weights → w4a16 software decode to bf16 + bf16 MFMA; A4W4 → the simulated arm (DOWN dequantizes fp4 activations, GLU keeps bf16 activations; bf16 MFMA), no native scaled MFMA; outputs differ from gfx950 beyond accumulation grouping.
* Before claiming a % of roof → use the target SKU's measured ceilings (MI300X: 4092 GB/s, bf16 937 / 1015 TF/s by shape, fp8 1889; MI325X: 4164 GB/s, bf16 wrapper 1063) and state which denominator.
* Before gating → check `asm_expect_gfx942.json` passes and `obj_baseline_gfx942.json` contract holds; rebuild into a fresh arch-qualified output dir (`build-amd/hsaco/gfx942`).
