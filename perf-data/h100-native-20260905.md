## FP8 prefill stage count: reject stage 2

`qwen-fp8-prefill-stages-h100-20260905.csv` compares the existing native
TMA/WGMMA FP8 primitive with two versus three stages at M=1024/4096/8192.
Each size covers eight Qwen projection shapes and two K-tail cases.
All 60 cases match the vLLM CUTLASS output bitwise; quantized activation
bytes/scales, output canaries and finiteness checks also pass.

Stage 2 takes 1.097–1.841 times the stage 3 latency across all 30 paired
shapes. Keep stage 3. Lower full-interpreter spills did not predict a win;
both primitive builds use 137 registers with no spills and cannot fit two
256-thread CTAs in one H100 SM. The full stage 2 object also omits unused
generic TMA GLU bodies, so its spill reduction is not solely a loop change.

## Live KV allocation candidate

`PLOW_VMM_LIVE=1` grows backing for packet-described full KV caches while
keeping virtual addresses stable. It requires both prefix-cache flags off
and skips prefix hashing, attachment, publishing and snapshots. Geometry
comes from packet instructions and declared tensor extents; no model
configuration is consulted. Sliding rings remain fully allocated.

The opt-in path accepts only validated BF16 cache readers/writers with
uniform full-cache geometry. Packed prefill, unsupported opcodes, FP8 KV
and batch > 1 KV tensormaps are rejected. The latter need per-slot
descriptors before serialized multi-slot TMA execution can be qualified.
The default is off. Existing prefix-cache behavior is unchanged.

CPU checks cover packet geometry, rejection paths and repeated allocator
growth/reset without prefix records. Actual Gemma12/31 B1 packets validate;
a batched Gemma12 TMA packet is rejected as intended. This does not yet
establish GPU capacity, model-output parity or a latency improvement.

## Empty prefill patch range fix

The layer 0 Qwen GDN block has no instruction patch sites. Its old inclusive
bounds remained `(22, 0)`, causing the upload count to wrap in a release
build before interpreter launch. The runtime now stores a half-open range,
skips empty uploads in both consumers, and derives upload bytes from a
bounded instruction slice. The packet and kernel arithmetic are unchanged.

Two CPU regressions cover empty and nonempty ranges. The previously failing
M=1024 checkpoint block now executes successfully with finite output.
Compute Sanitizer exited before its first instrumented API call; this is
not a sanitizer pass. The fix is isolated in `b5a1833` on the performance
branch and cherry-picked as `fc655bd` for main integration.

`qwen-fp8-role-block-parity-20260905.json` records all 18 fresh block checks:
GDN layer 0 and full-attention layer 3, M=1024/4096/8192, coarse/isolated/role
packets. Every output is finite and bitwise identical across the three
packet modes at each layer/size. All use the same fixed runtime binary,
checkpoint and deterministic synthetic hidden input. This qualifies first
exact-bucket output parity only; continuation state, HF parity and warmed
block/serving timing remain separate gates. The root vLLM reference driver
resumed after GPU cleanup at 16:37:38 UTC.
